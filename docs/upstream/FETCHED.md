# Upstream documentation snapshot — USDA WAOB World Agricultural Supply and Demand Estimates

Source of truth for every endpoint wrapper and parser (ADR-0003, ADR-0020). The files in
this directory are written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from
the pages in the table below and refreshed deliberately by PR, so that changes show up
as diffs. This file is generated by the same script; nothing here is edited by hand
except `layout.md`, the file layouts as observed, which its row describes.

publisher's objection is met by replacing it with a summary that keeps the names and
semantics the package relies on.

## How this is captured

The two ESMIS pages, the publication page of the World Agricultural Supply and Demand
Estimates and the page of its newest release, are converted to Markdown, and so are five
pages of the World Agricultural Outlook Board (WAOB): its WASDE page and the four pages
that page's menu links, About WASDE, the FAQ, Historical Changes & Revisions and the
historical data page. The newest release is the first row of the publication page's
release list, read from its View link on every run; the run stops when that row is not
the page's Latest Release. www.usda.gov answers 403 Access Denied at its CDN edge to an
automated request for some of WAOB's pages. The script asks www.usda.gov first: a page
it serves is kept from there, and a page it refuses is recorded by its status at its
www.usda.gov URL and kept from https://usda.azureedge.us, the CDN origin that
www.usda.gov fronts, which serves the same Drupal site at the same paths; the canonical
URL is the www.usda.gov one, and each Markdown file kept from the CDN origin names both.
The 2018 notice of the file names is kept byte for byte as a PDF; the script does not
read its text, so a change to it shows in its sha256. In this run www.usda.gov served
`pages/about-wasde.md` itself and refused `pages/wasde-report.md`,
`pages/wasde-faqs.md`, `pages/historical-changes-revisions.md`,
`pages/historical-wasde-report-data.md`, `New_WASDE_Filename_Format.pdf`, which are kept
from the CDN origin.

The Markdown is `markdownify`'s rendering of the page's `<main>` element, with headings
in ATX style. Breadcrumbs, menus and the other navigation, forms (the release list's
date filter), buttons, images and icons, share links and screen-reader-only text are
dropped; a `<time>` keeps its `datetime` attribute in parentheses after its text, a link
with a `type` attribute (an ESMIS release file's media type) keeps it in parentheses
after the link, two links side by side get a space between them, a no-break space
becomes a space, an emphasis holding only spaces becomes a space, and a line break that
ends a paragraph is dropped; trailing spaces are removed. Links are kept as the page
prints them: a link starting with `/` is relative to the site the page was served from,
which for WAOB's pages is www.usda.gov as well. No table on these pages has merged cells
or a nested table; the run stops on one, and on a page whose `<h1>` is not the one the
script expects. The ESMIS pages change with every release.

Not snapshotted: ESMIS's release calendar, which xippios-usda-esmis keeps as an excerpt;
the data files the historical data page links (CSV, ZIP); the release files themselves.
No upstream page documents the layout of the XML, XLS or TXT files: `layout.md`
describes them as observed in release files, by hand, and says what it was written from;
its row records no fetch.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Bytes and sha256 are those of the body as fetched: a converted page's row
holds the HTML page's. Last-Modified is the HTTP header in UTC, ETag as sent; Drupal
sets both to the time it last rendered the page, so they change with a new rendering of
the same page. A page recorded without a file is `(no file)`, and one recorded by its
status only, a 403 whose body carries a per-request reference or a page-not-found page,
has no size, sha256 or validators. Requests go one at a time, 2 s apart, each retried at
most once, identified as `xippios-usda-wasde refresh_upstream
(+https://github.com/xippios)`; no API key is sent or read.
